SSH acesso remoto, túneis, chaves · M3

ssh [-p <porto>] <utilizador>@<host> ["<comando>"]
  • Sem utilizador usa o teu nome local. Alternativa: ssh -l <utilizador> <host>.
  • Com "<comando>" corre só esse comando no servidor e volta (sem sessão interativa).
ssh -N -L <portoLocal>:<destino>:<portoDestino> <utilizador>@<servidorSSH>
  • Túnel LOCAL: abre <portoLocal> na TUA máquina. O <destino> é visto a partir do servidor SSH (localhost = o próprio servidor).
  • Depois apontas o programa (browser, email…) para localhost:<portoLocal>.
ssh -N -R <portoRemoto>:<destino>:<portoDestino> <utilizador>@<outraMáquina>
  • Túnel REVERSO: corre-se no SERVIDOR; o porto abre na OUTRA ponta (a máquina a que te ligas).
ssh -N -D <portoSOCKS> <utilizador>@<servidorSSH>
  • Proxy SOCKS: no browser → SOCKS v5, host localhost, porto <portoSOCKS>.
scp [-P <porto>] [-r] <origem> <destino>
  • O lado remoto escreve-se <utilizador>@<host>:<caminho> — os «:» são obrigatórios.
  • «.» = pasta atual (ou a home remota, se vier logo depois dos «:»).
ssh-keygen -t <ed25519|rsa> [-b <bits>] → ssh-copy-id <utilizador>@<host> → ssh-add

iptables firewall · M4 · template do professor

$IPT [-t <tabela>] -A <CHAIN> [-i|-o <placa>] [-p <proto>] [-s <origem>] [-d <destino>] [--sport <p>] [--dport <p>] [-m state --state <ESTADOS>] -j <ALVO>
  • Lê-se: «acrescenta à CHAIN uma regra: se o pacote for assim, então ALVO».
  • Estilo do professor: o -j pode vir logo a seguir ao $IPT → $IPT -j ACCEPT -A OUTPUT -p tcp … (é igual).
Cliente: $IPT -A OUTPUT -p <tcp|udp> --sport $DYN --dport <PORTO> -m state --state NEW -j ACCEPT
  • Eu começo a ligação → o 1.º pacote SAI (OUTPUT). O porto do serviço é o de DESTINO.
Servidor: $IPT -A INPUT -p <tcp|udp> --sport $DYN --dport <PORTO> -m state --state NEW -j ACCEPT
  • Os outros ligam-se a mim → o 1.º pacote ENTRA (INPUT). O porto do serviço continua a ser o de DESTINO.
REDIRECT: $IPT -t nat -A PREROUTING -p tcp --dport <DE> -j REDIRECT --to-ports <PARA>
  • E na filter aceita-se o porto <PARA> (o já traduzido), não o <DE>.

Squid proxy · /etc/squid/squid.conf · M5

acl <nome> <tipo> <valor> [<valor> …]
  • Só define uma lista (sozinha não faz nada). O nome é inventado por ti.
  • Várias linhas acl com o MESMO nome somam valores (= OU).
http_access <allow|deny> [!]<acl> [[!]<acl> …]
  • Na MESMA linha = E (todas têm de bater). Linhas diferentes = lidas de cima para baixo, a 1.ª que bate decide.
  • ! = negação. Termina sempre com http_access deny all.
http_port <porto> [intercept]
  • 3128 = proxy normal (configurado no browser); 3129 intercept = proxy transparente.

Molde — como se monta a linha

sudo nmap [descoberta] [tipo de scan] [-p <portos>] [deteção] [-T<0-5>] [-n] [saída] <alvo>
  • A ordem das opções é livre; o costume é pôr o <alvo> no fim.
  • <alvo> = 192.168.1.10 · 192.168.1.0/24 · 192.168.1.1-50 · www.site.pt · -iL lista.txt · -iR 100
  • Exemplo: sudo nmap -sS -p22,80,443 -sV -T4 -n 192.168.1.10
  • Quase tudo precisa de sudo (pacotes «raw»). Sem sudo só funciona o -sT.
  • Listas de portos das sondas vão coladas: -PS22,80 (sem espaço!). No -p tanto faz: -p22,80 ou -p 22,80.
  • Só 1 tipo de scan TCP de cada vez (-sS -sA dá erro). TCP + UDP pode: -sS -sU.
  • -sn = só descobre hosts (sem portos). -Pn = salta a descoberta e vai direto aos portos.
  • Nomes antigos dos slides: -sP → -sn · -P0/-PN → -Pn.
  • Sem -p o nmap faz os 1000 portos mais comuns. Sem tipo de scan usa -sS (com sudo).

    Opções

    Alvo (o que vai no fim)

    <IP>

    Um só host.

    sudo nmap 192.168.1.10
    <rede>/<bits>

    Rede inteira (/24 = 256 endereços).

    sudo nmap -sn 192.168.1.0/24
    <a.b.c.x>-<y>

    Intervalo de IPs.

    sudo nmap 192.168.1.1-50
    <nome DNS>

    Um nome (precisa de DNS/Internet → no teste só escrever).

    sudo nmap -sV www.ipleiria.pt
    -iL <ficheiro>

    Lê os alvos de um ficheiro (um IP ou rede por linha).

    sudo nmap -iL ips.txt
    -iR <n>

    n IPs aleatórios da Internet (0 = sem fim). Precisa de Internet.

    sudo nmap -iR 100 -p995 --open
    --exclude <IPs>

    Tira IPs do alvo (ex.: o teu).

    sudo nmap -sn 192.168.1.0/24 --exclude 192.168.1.5

    Descoberta de hosts (fase 1) — quem está ligado?

    -sn

    Só descobre que hosts estão ativos. NÃO faz scan de portos. Nos slides aparece -sP (nome antigo).

    sudo nmap -sn 192.168.1.0/24
    -Pn

    Salta a descoberta: assume que todos estão ativos e faz scan de portos na mesma. Usa-se quando o host não responde a ping. Numa rede inteira demora muito mais.

    sudo nmap -Pn 192.168.1.10
    -PS<portos>

    TCP SYN: envia SYN para esses portos. SYN/ACK (aberto) ou RST (fechado) = host ativo. Usa portos comuns (22, 25, 80…).

    sudo nmap -sn -PS22,25,80 192.168.1.0/24
    -PA<portos>

    TCP ACK: envia um ACK de uma ligação que não existe; o host responde RST e revela-se. Passa firewalls mal configuradas que só bloqueiam SYN de entrada. Não passa firewalls stateful. Junta-se ao -PS para descobrir mais hosts.

    sudo nmap -sn -PS22,25,80 -PA21,23,80,3389 192.168.1.0/24
    -PU<portos>

    UDP: porto fechado responde «ICMP port unreachable» = host ativo. Por omissão usa o 40125; o 53 também serve. Passa firewalls que só vigiam TCP.

    sudo nmap -sn -PU53,40125 192.168.1.0/24
    -PE

    ICMP echo (o ping normal). Pouco fiável: muitos hosts e firewalls bloqueiam.

    sudo nmap -sn -PE 192.168.1.0/24
    -PP

    ICMP timestamp request — alternativa quando o ping normal é bloqueado.

    sudo nmap -sn -PP -PM 192.168.1.0/24
    -PM

    ICMP address mask request — outra alternativa ao ping.

    sudo nmap -sn -PP -PM 192.168.1.0/24
    -PR

    ARP: só na mesma LAN; o mais rápido e fiável. Na mesma rede o nmap usa ARP mesmo que peças outro método.

    sudo nmap -sn -PR 192.168.1.0/24
    -PO<protocolos>

    IP protocol ping: pacotes IP com esses protocolos (omissão: 1 ICMP, 2 IGMP, 4 IP-in-IP). É a letra O, não zero.

    sudo nmap -sn -PO1,2,4,6 192.168.1.0/24

    Tipo de scan de portos (fase 2) — escolhe 1 TCP (+ -sU)

    -sS

    TCP SYN («half-open»): o padrão. Envia SYN: SYN/ACK = open, RST = closed, nada = filtered. Não completa a ligação → rápido e discreto.

    sudo nmap -sS -T4 192.168.1.10
    -sT

    TCP connect: faz a ligação completa. Lento e fácil de detetar. O único que funciona sem sudo.

    nmap -sT 192.168.1.10
    -sU

    UDP. Lento. Fechado → ICMP port unreachable (closed); sem resposta → open|filtered. Junta-se a um scan TCP.

    sudo nmap -sU -p53,161 192.168.1.10
    -sN

    TCP NULL: nenhuma flag. RST = closed · nada = open|filtered · ICMP unreachable = filtered. Passa algumas firewalls stateless; não funciona contra stateful.

    sudo nmap -sN 192.168.1.10
    -sF

    TCP FIN: só a flag FIN. Mesmas respostas do -sN. Serve para cruzar com o -sS (ver «Ler o output»).

    sudo nmap -sF -T4 192.168.1.10
    -sX

    TCP Xmas: flags FIN + PSH + URG («árvore de Natal»). Mesmas respostas do -sN.

    sudo nmap -sX -T4 192.168.1.10
    -sA

    TCP ACK: não diz se está open ou closed. Serve para mapear a FIREWALL (stateless/stateful e que regras tem). RST = unfiltered (passou a firewall); nada ou ICMP = filtered.

    sudo nmap -sA -T4 192.168.1.10
    -sW

    TCP Window: como o ACK, mas olha para o campo window do RST: window > 0 → open, = 0 → closed (só em alguns sistemas).

    sudo nmap -sW 192.168.1.10
    -sM

    TCP Maimon: flags FIN + ACK. Alguns BSD não respondem quando o porto está aberto.

    sudo nmap -sM 192.168.1.10
    -sI <zombie>[:porto]

    Idle scan: o mais furtivo — os pacotes parecem vir do «zombie» (o IDS vê o zombie, não tu). Usa-se com -Pn.

    sudo nmap -Pn -sI 192.168.1.50 192.168.1.10
    -sO

    IP protocol scan: descobre os protocolos IP suportados (TCP, UDP, ICMP, IGMP…), não portos. O -p passa a ser números de protocolo.

    sudo nmap -sO 192.168.1.10

    Portos

    -p<portos>

    Escolhe os portos: um, lista ou intervalo.

    sudo nmap -p22 192.168.1.10
sudo nmap -p22,80,443 192.168.1.10
sudo nmap -p1-1024 192.168.1.10
    -p-

    TODOS os portos (1 a 65535).

    sudo nmap -p- 192.168.1.10
    -p U:<udp>,T:<tcp>

    Portos UDP e TCP no mesmo scan (com -sU + um scan TCP).

    sudo nmap -sS -sU -p U:53,161,T:22,80 192.168.1.10
    -F

    Rápido: só os 100 portos mais comuns. (extra)

    sudo nmap -F 192.168.1.10
    --top-ports <n>

    Os n portos mais comuns. (extra)

    sudo nmap --top-ports 20 192.168.1.10

    Deteção: versão, sistema operativo, scripts

    -sV

    Deteta a versão dos serviços (ex.: OpenSSH 9.6, Apache 2.4). Serve para ver se estão atualizados ou se há serviços estranhos (backdoors). Dispara o IDS.

    sudo nmap -sV -p80,443 192.168.1.10
    -O

    Deteta o sistema operativo (letra O maiúscula). Precisa de sudo.

    sudo nmap -O 192.168.1.10
    -A

    Agressivo = -O + -sV + scripts default (-sC) + traceroute, tudo de uma vez.

    sudo nmap -A -T4 192.168.1.10
    -sC

    Corre os scripts NSE «default» (os seguros). Igual a --script default.

    sudo nmap -sC 192.168.1.10
    --script <nome>

    Corre um script NSE. O vulners precisa de -sV (cruza as versões com a base de CVE) e de Internet.

    sudo nmap -sV --script vulners 192.168.1.0/24
sudo nmap --traceroute --script traceroute-geolocation 8.8.8.8
    --traceroute

    Faz traceroute até ao alvo (o script traceroute-geolocation precisa dele).

    sudo nmap --traceroute 8.8.8.8

    Tempo e furtividade

    -T<0-5>

    -T0 5 min entre pacotes · -T1 15 s (para não disparar o IDS) · -T2 0,4 s · -T3 padrão · -T4 o recomendado pelo autor (paralelo) · -T5 5 ms (o mais agressivo).

    sudo nmap -T4 192.168.1.10
    -n

    Não resolve nomes (DNS) → muito mais rápido. Usa quase sempre.

    sudo nmap -n -sn 192.168.1.0/24
    --source-port <porto> (ou -g)

    Usa esse porto de ORIGEM. O 53 (DNS) é muitas vezes deixado passar pelas firewalls.

    sudo nmap -sS --source-port 53 192.168.1.10
    --max-rtt-timeout <n>ms

    Afinar a espera pelas respostas. Escreve ms: sem unidade o valor é em segundos (os slides escrevem só 200).

    sudo nmap -n -T4 --max-rtt-timeout 200ms --initial-rtt-timeout 150ms -Pn -p80 192.168.1.0/24
    --send-eth

    Envia tramas ethernet em bruto em vez de usar a pilha IP do SO.

    sudo nmap -sn -PR --send-eth 192.168.1.0/24
    --spoof-mac <fabricante|MAC>

    Falsifica o MAC de origem (Apple = MAC aleatório da Apple).

    sudo nmap -sn -PR --send-eth --spoof-mac Apple 192.168.1.0/24

    Saída (guardar / mostrar)

    -oN <ficheiro>

    Guarda o output normal (como no ecrã).

    sudo nmap -sn -oN nmapOut.txt 192.168.1.0/24
    -oG <ficheiro>

    Formato «grepable»: uma linha por host, fácil de filtrar com grep/cut.

    sudo nmap -p80 -oG web.gnmap 192.168.1.0/24
    -oX <ficheiro>

    XML (é o que o ndiff compara).

    sudo nmap -sS -oX sS.xml 192.168.1.10
    -oA <base>

    Os 3 de uma vez: base.nmap, base.gnmap e base.xml.

    sudo nmap -sS -oA scan1 192.168.1.10
    -v / -vv

    Verbose: mais detalhe (mostra os portos à medida que os encontra).

    sudo nmap -v -p22 192.168.1.0/24
    --open

    Só mostra os portos abertos (e só os hosts que os têm).

    sudo nmap -p3306 --open 192.168.1.0/24
    --reason

    Mostra porque é que cada porto ficou nesse estado (syn-ack, reset, no-response). (extra)

    sudo nmap --reason -p22,80 192.168.1.10

    Comparar scans

    ndiff <a.xml> <b.xml>

    Compara 2 scans guardados em XML (hosts, portos, versões, SO). Linhas com - = do 1.º scan; + = do 2.º. É um pacote à parte (ndiff): pode não estar instalado.

    sudo nmap -n -sS -oX sS.xml 192.168.1.10
sudo nmap -n -sF -oX sF.xml 192.168.1.10
ndiff sS.xml sF.xml

    Ler o output

    open
    Há um serviço a escutar e a aceitar ligações.
    closed
    Ninguém escuta nesse porto (o host respondeu RST), mas pode começar a qualquer momento.
    filtered
    Algo (firewall) bloqueia — sem resposta ou ICMP unreachable. Não dá para saber se está open ou closed. Uma regra DROP dá isto.
    unfiltered
    Responde (RST), mas não dá para dizer se open ou closed. Só aparece no -sA.
    open|filtered
    Sem resposta em -sU, -sN, -sF ou -sX: pode estar aberto ou filtrado. Inconclusivo.
    closed|filtered
    Só no -sI (idle).
    Not shown: 998 filtered ports
    Os 998 portos que não aparecem na lista estão todos nesse estado.
    MAC Address: 00:0C:29:AB:CD:EF (VMware)
    MAC + fabricante da placa. Só aparece na mesma LAN (o MAC não atravessa routers).
    Nmap done: 256 IP addresses (12 hosts up)
    Resumo: quantos IPs foram vistos e quantos estão ativos.
    Cruzar -sS com -sF
    -sS: 2 open + 998 filtered · -sF: 3 open|filtered + 997 closed → dos 998 filtered, 997 estão closed; o que fica filtered num e open|filtered no outro continua inconclusivo.
    filtered + open|filtered
    → o porto está filtered.
    unfiltered (-sA) + open|filtered
    → o porto está open.
    REJECT --reject-with tcp-reset
    No nmap aparece closed. DROP (ou REJECT por omissão, com ICMP) aparece filtered.

    You requested a scan type which requires root privileges. QUITTING!

    Molde — como se monta a linha

    $IPT [-t <tabela>] -A <CHAIN> [-i|-o <placa>] [-p <proto>] [-s <origem>] [-d <destino>] [--sport <p>] [--dport <p>] [-m state --state <ESTADOS>] -j <ALVO>
    • Lê-se: «acrescenta à CHAIN uma regra: se o pacote for assim, então ALVO».
    • Estilo do professor: o -j pode vir logo a seguir ao $IPT → $IPT -j ACCEPT -A OUTPUT -p tcp … (é igual).
    Cliente: $IPT -A OUTPUT -p <tcp|udp> --sport $DYN --dport <PORTO> -m state --state NEW -j ACCEPT
    • Eu começo a ligação → o 1.º pacote SAI (OUTPUT). O porto do serviço é o de DESTINO.
    Servidor: $IPT -A INPUT -p <tcp|udp> --sport $DYN --dport <PORTO> -m state --state NEW -j ACCEPT
    • Os outros ligam-se a mim → o 1.º pacote ENTRA (INPUT). O porto do serviço continua a ser o de DESTINO.
    REDIRECT: $IPT -t nat -A PREROUTING -p tcp --dport <DE> -j REDIRECT --to-ports <PARA>
    • E na filter aceita-se o porto <PARA> (o já traduzido), não o <DE>.
    • --sport/--dport só depois de -p tcp ou -p udp; --icmp-type só depois de -p icmp.
    • --state só depois de -m state; --limit/--limit-burst só depois de -m limit.
    • Opções do alvo vêm depois do seu -j: --reject-with (REJECT), --log-prefix (LOG), --to-ports (REDIRECT).
    • -i só em INPUT/FORWARD/PREROUTING; -o só em OUTPUT/FORWARD/POSTROUTING.
    • Lê-se de cima para baixo e a 1.ª que bate decide (o LOG regista e continua). Exceções (DROP de uma rede) vêm ANTES do ACCEPT geral.
    • -P só aceita ACCEPT ou DROP (REJECT não pode ser política). Listas sem espaços: ESTABLISHED,RELATED, -d 8.8.8.8,1.1.1.1.

      Molde — como se monta a linha

      acl <nome> <tipo> <valor> [<valor> …]
      • Só define uma lista (sozinha não faz nada). O nome é inventado por ti.
      • Várias linhas acl com o MESMO nome somam valores (= OU).
      http_access <allow|deny> [!]<acl> [[!]<acl> …]
      • Na MESMA linha = E (todas têm de bater). Linhas diferentes = lidas de cima para baixo, a 1.ª que bate decide.
      • ! = negação. Termina sempre com http_access deny all.
      http_port <porto> [intercept]
      • 3128 = proxy normal (configurado no browser); 3129 intercept = proxy transparente.
      • As acl vêm ANTES das http_access que as usam.
      • As tuas http_access ficam ANTES do http_access deny all (no ficheiro original há a linha «INSERT YOUR OWN RULE(S) HERE»).
      • Ordem típica: 1.º os deny «sempre» (sites/ficheiros proibidos), depois os allow com condições, no fim deny all.
      • .youtube.com (com ponto) = o domínio + todos os subdomínios; youtube.com = só esse nome.
      • Dias no time: S=dom M=seg T=ter W=qua H=qui F=sex A=sáb. Horas HH:MM-HH:MM (a 1.ª menor que a 2.ª).
      • Depois de mudar: sudo squid -k parse (verifica) e sudo squid -k reconfigure (aplica).

      Molde — como se monta a linha

      openssl enc -<cifra> -pbkdf2 [-a] -in <entrada> -out <saída> [-pass pass:<password>]
      • Decifrar = o MESMO comando + -d (com as mesmas opções: cifra, -pbkdf2/-iter, -a).
      • Ex.: openssl enc -aes-256-cbc -pbkdf2 -a -in report.pdf -out report.enc
      openssl base64 [-d] -in <entrada> -out <saída>
      • Só codifica/descodifica base64 — não cifra.
      gpg -c [-a] [--cipher-algo AES256] <ficheiro> · gpg -o <saída> -d <ficheiro.gpg>
      • As opções vêm ANTES do ficheiro.
      steghide embed -cf <capa.jpg> -ef <segredo> · steghide extract -sf <imagem.jpg> · steghide info <imagem.jpg>
      • cf = cover file · ef = embed file · sf = stego file · xf = extract file
      sha256sum <ficheiro>… · sha256sum -c <lista> · printf '<texto>' | sha256sum
      • Cifrar e decifrar com as mesmas opções (algoritmo/modo, -pbkdf2/-iter, -a). Se não: bad decrypt ou bad magic number.
      • Sem -pbkdf2 o OpenSSL 3 funciona mas avisa: *** WARNING : deprecated key derivation used.
      • Cifrar 2× com a mesma password dá resultados diferentes: salt aleatório → chave e IV diferentes (o ficheiro começa por Salted__; em base64 U2FsdGVkX1).
      • ECB cifra cada bloco sozinho (blocos iguais → cifrado igual, mostra padrões; sem IV). CBC mistura cada bloco com o anterior e o 1.º com o IV.
      • O steghide altera a própria capa no embed → guarda uma cópia antes. Por omissão comprime e cifra (AES-128 = rijndael-128, cbc). Só JPEG, BMP, WAV, AU.
      • Hash ≠ cifra: tamanho fixo, determinista, efeito avalanche, só de ida (não se «decifra»).
